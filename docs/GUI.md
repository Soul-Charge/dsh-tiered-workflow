# 设置页使用说明（Web GUI）

本插件在 DSH Web GUI 的「设置」里注册一个整页分区 **专家桥**（英文 **Expert Bridge**）。它编辑的是本插件在 profile 里的配置项，数据落在 `cordis.patch.yml` 的 `expert-bridge` 条目上。

> 本页只能写「可写字段」。`systemPromptFile`、`usageLog`、`debugLog`、`reminder.text` 这些环境路径与长文案**不在页面上**，继续手改 patch 文件。

## 1. 打开方式

左下角「设置」→ 左栏找 **专家桥**。

宿主没有服务 `expert-bridge` 这个设置命名空间时，这一页**根本不会出现**（不是显示一个空壳）。出现不了通常意味着：插件没装、条目被禁用、组合被拒。先重启 DSH 再看。

## 2. 六个分区

| 分区 | 内容 |
|---|---|
| 专家列表 | `ask_expert` 用的专家条目（可带 `tags` / `note` / 附加 `systemPrompt`） |
| 低档子代理 | `delegate({tier:'low'})` 用的模型清单（只读**软约束**，见 §4） |
| 中档子代理 | `delegate({tier:'medium'})` 用的模型清单 |
| 运行参数 | `maxTokens`、`timeoutMs`、`minPackageChars`、`reminder.threshold` |
| 提醒开关 | `reminder.enabled` |
| 保存 / 放弃 | 一次提交全部改动；放弃则重新读取宿主当前值 |

## 3. 清单条目怎么填

每条的顺序就是匹配顺序，可用 ↑ / ↓ 调整。

| 字段 | 说明 |
|---|---|
| 名称（可空） | 给人看的标签，回执与 usage 记账里会用到 |
| 备注（可空） | 自己看的说明，不参与匹配 |
| 供应商路由 / 模型 | 都来自 DSH 当前可路由模型目录（`session/modelCatalog`），**没有**写死任何供应商 |
| 推理档位 | 该模型对外公布的档位；留空 = 用模型默认 |
| 标签 | 逗号分隔（中英文逗号都行），去首尾空白、丢空项、去重，大小写原样保存 |
| 附加系统提示 | 仅专家条目有；非空时拼在全局 `CONSULTANT-SYSTEM.md` 之后 |

**标签匹配规则**：`ask_expert({need})` / `delegate({need})` 会去目标清单里找**第一条** `tags` 含 `need` 的条目（双方先 trim，再大小写不敏感比较）。没给 `need`，或者没有一条命中，就取该清单里**第一条 provider 与 model 都非空**的条目。

「供应商与模型要么都选，要么都留空」：只填一半的条目会标红并且**阻止保存**——半配置的路由在调用时只会报错。

## 4. 低档子代理的「只读」是软约束

低档档位的定位是做简单杂活（搜索、阅读、整理）。它的「只读」**是通过在委派时把只读要求写进子代理提示实现的**：宿主侧没有强制工具限制，子代理理论上仍能调用写文件的工具。

因此：

- 不要把它当成安全边界，重要文件不要交给低档档位去改；
- 需要真正动手时，用中档档位；
- 任何文档都不应声称低档是「强制只读」。

## 5. 为什么是「一次保存」而不是逐项自动保存

宿主把三张清单声明成**整数组 volatile**（和官方 `allowedModels` 同款），页面只能整表替换，不能逐元素写。所以本页把所有改动收集起来，点「保存」时用**一次** `settings.mutate` 提交：

```
{ op:'set', path:['experts'], value:[...] }
{ op:'set', path:['delegates','low'], value:[...] }
{ op:'set', path:['maxTokens'], value:8000 }
```

好处是不会写出「改了一半」的配置；代价是改动在点保存前不生效。

保存前页面只做**字段级**冲突判定：对本次真正要写的每个 path，比较「打开页面时读到的基线值」与「宿主当前值」。值没变就直接写，栅栏用宿主**当前** revision——所以插件热挂载、配置文档整体重载这类只是 revision 前移的情况**不会**再挡人。只有「我要写的字段确实被别人改了」才会判冲突。

## 6. 写不进去时的排查顺序

页面上的状态提示已经区分了几种情况，按它给的线索看：

| 现象 | 含义 | 处理 |
|---|---|---|
| 「宿主还没有提供 expert-bridge 这个设置命名空间」 | 插件没装 / 条目没启用 / 组合被拒 | 检查 profile 的 `cordis.patch.yml` 与 `package.json`，重启 DSH |
| 「当前设置文档为只读」 | 部署层或命令行覆盖使文档不可写 | 去掉覆盖，或改 patch 文件 |
| 「宿主拒绝了这次写入」 | 命名空间未注册，或字段不被接受——**Config 与页面字段不一致时就是这个样子** | 看宿主日志；确认插件版本与页面版本一致 |
| 「设置已在别处被修改…（期望 revision X，实际 Y）」 | 你正要写的字段被别处改了（**不**包括单纯 revision 前移） | 括号里是诊断信息；点「放弃修改」重新读取，再改一遍 |
| 「模型目录读取失败 / 没有提供模型目录接口」 | `remote.session.modelCatalog` 不可用 | 下拉里仍会保留原值并标注；可临时手改 patch |
| 下拉里的值显示「（当前目录中不存在，已保留原值）」 | 该 provider/model 已不在目录里（供应商被删或下线） | 重新选一个，或保留原值确认它仍可用 |

另外，宿主侧拒绝写入时页面会**自动重试一次**（等镜像给出新 revision，再用同一批改动写一遍）；两次都失败才显示上面的失败文案，草稿始终保留。

## 7. 生效方式

保存成功后**立即生效**，不需要重启 DSH：写入走官方 settings 服务，会重解析插件条目，运行期每次调用都会重新读配置值。

## 8. 已知限制

- 页面不编辑 `systemPromptFile` / `usageLog` / `debugLog` / `reminder.text`（环境路径与长文案，走 patch）。
- 清单条目的 `provider` / `model` 只是字符串，页面不会替你校验该路由此刻是否可用；目录里消失的旧值会标注但仍可保存。
- 页面不提供「导出/导入」；需要备份就用 git 管理 profile 的 `cordis.patch.yml`。
