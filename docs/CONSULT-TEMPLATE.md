# 求助包模板（ask_expert 用）

> 本文件是「卡住时向专家模型求助」的填写模板。**发包前先读本文件**，按第 1 节填；填不出来的字段=不许发。
> 用法：把整份模板填好，作为 `ask_expert` 的 `package` 参数传入。执行者人设里只需放压缩版并指向本文件。

## 1 主模板（整包 ≤120 行；标【必】的字段填不出=不许发，回去干活）

```
# 求助包（整包≤120行；标【必】的字段填不出=不许发，回去干活）

## 0 头部【必】
类型: A因果 / B转译 / C判据 / D长尾   (选一个主类型,按第 5 节增删)
卡型: 方向错误型 —— 依据: ___
      (写一句"事实我都拿得到,但解释不了___";若缺的是事实=信息不足型,不发,去取证)
第几次: 第_次尝试 / 跨_个会话 / 用户已纠偏_次 / 自上次用户发言后工具调用_次

## 1 目标与根治定义【必·可留出口：写不出就明写「写不出」，并把问题改成「根治该怎么定义」，交给专家定义】
目标: 一句话,写用户要的效果,不写我打算用的手段
根治 = 以下全部成立(2–5条,每条能判 是/否):
- [ ] ___  (至少一条覆盖"历史上复发的那个场景")
- [ ] ___  (至少一条是禁止项:不许靠哪种补丁达成,如硬编码偏移、再加一个关键词)
非目标: ___

## 2 背景(≤4行)
技术栈+版本 / 绝对路径 / 一行箭头链说明数据或调用怎么流经这里

## 3 症状【必】
期望: ___    实际: ___    复现: 必现 / 偶现(条件___)
(只写可观测现象,禁用"不对/不好/歪了")

## 4 历史【必;确实首次则写"首次"】
第1次(会话_): 假设___ → 做法___ → 结果___ → 当时是否自称修好?后来怎么复发?
第2次 ...
这次不同在: ___  (写不出不同=又在重复,第10节只许问"我的前提哪条错了")

## 5 已证伪的假设【必·抄,≥2条;每条必须带一行原始输出或用户原话——只有「试了不行」不算】
H1: 我以为___ → 我做了___ → 我亲眼看到___ → 所以不成立
H2: ...
(只有"试了没用"而没有观测,不算一条)

## 6 我的判断【前半必·后半推荐；「我猜专家会说」写不出不算不合格，但猜得出能验证就别发】
当前最可能的假设: ___,把握_成;它解释不了的现象: ___
取舍: 方案甲(代价___) vs 方案乙(代价___),我倾向_,因为___
我猜专家会说: ___
  → 猜得出且10分钟内能验证: 不发,去验证
  → 猜不出,或猜到的答案已被第5节排除/解释不了上面那个现象: 可以发

## 7 可观测中间态【推荐；写不出的代价是专家会建议你先造探针】
我能直接看到: ___ (能打印的变量/能查的状态/能跑的最小用例)
我看不到: ___
改动后用___判断"生效",用___判断"没生效"  (写不出=先造探针再发)

## 8 类型差异段(≤12行,见第 5 节)

## 9 证据(≤50行,至少1段原文;规则见第 3 节)

## 10 一个问题【必】
只一个,问方向/前提/取舍。句式三选一:
 "假设X与Y哪个更可能?用什么最小观测能区分?"
 "前提P1–Pn里哪条最可能是错的?"
 "第1节的根治定义是否有漏洞或不可判定?"

## 11 约束
不可改动: ___    需用户批准(不可逆): ___

## 12 输出要求(原样保留,不改)
≤3条建议,每条含:为什么 + 用第7节哪个观测验证 + 预期看到什么。
方向或前提错了就直接否决并指出是哪条。信息不足以判断时,只说缺哪一个观测,不要猜。
不要给整段替换代码;涉及不可逆操作必须标注。
```

## 2 行数预算

证据 ≤50 行，类型差异段 ≤12 行，其余 ≤58 行。

## 3 证据节规则

```
1. 每段开头一行标头: [原文|转述] 来源(文件:行号 / 命令 / 用户第N次发言) —— 支持或反驳哪条(H几/P几)
   挂不上任何假设的片段,删掉。
2. 日志: 只留"第一处异常 ±5行";重复行折叠成"(同上 ×N)";省略处写"…(略N行)"。
3. 代码: 贴 diff 或"函数签名+关键10行",不贴整文件。
4. 能对照就对照: "好的那次 vs 坏的那次"只贴差异行。
5. 截图专家看不到: 换成数值(坐标/角度/尺寸/第几帧),或逐条写"哪个元素现在在哪、应该在哪"。
6. 用户反馈必须[原文]照抄,不许概括。
7. 上限: ≤5段,每段≤12行,合计≤50行。超了说明还没想清哪条证据重要。
```

## 4 把主观标准翻译成可判定条件（B/C 两类必用）

| 用户原话 | 翻译成 | 写出来的样子 |
|---|---|---|
| "不好看/达不到审美" | 参照物 + 逐项差异 | "顶栏像 X 截图:左对齐、字号比正文大两级、与正文间距 1 行;上一版错在居中且间距 3 行" |
| "该停就停/别抢话" | 场景 → 期望行为 → 实际行为 | "用户说'行了' → 期望:回复 ≤1 句且不提新建议 → 实际:追加 3 条建议" |
| "非平凡/要有深度" | 淘汰测试 + 正反例 | "删掉这条,读者少知道什么?答不出就是平凡",附 2 个好例 2 个坏例 |
| "这是治标" | 复发条件 | "换一个没见过的输入___,问题是否重现" |
| 3D/版式"变形" | 可量的尺寸与关系 | "A 在 B 正上方,间距 = A 高度的 1/2,左缘对齐;实际 A 偏右 0.3 单位" |

写不出参照物或样例时，缺的是用户的信息，应该问用户，不是问专家。

## 5 四份类型差异段

```
【A 因果】多写:
链路: 来源① → 来源② → 合并/覆盖点 → 生效点,每环标 [已证实:怎么证的] 或 [推测]
我以为谁覆盖谁: ___ (依据: 文档/源码/猜)
最小对照: 改_时生效 / 改_时不生效,二者唯一差异: ___
读取探针: 我怎么知道"这份配置被读到了": ___
升级类加写: 升级前后版本号;补丁打在哪个文件哪个函数;该处上游变没变 [已查/未查]
少写: 根治压到2条(生效可判定 + 升级后不会静默失效);不需要用户原话。
问题句式: "链路里我标[推测]的哪一环最可能错了?"
```

```
【B 转译】多写:
用户原话[原文]: 逐条照抄全部相关发言
我转译的规格(逐条可核对): 1.___ 2.___
歧义词: "___" 我按_理解,另一种读法是_
参照物: 像___(具体到哪个产品/文件/截图的哪个部位);不像___(上一版,错在规格第_条)
设计/实现分离: 规格经用户确认过吗 [是/否];把这份规格交给完美的实现者,用户会满意吗 [会/不确定]
已交付版本: v1 做成___ → 用户反应[原文];v2 ...
少写: 第5节可用"已交付版本+用户反应"代替证伪假设;证据以原话和规格为主,少贴代码。
问题句式: "规格第几条最可能误读了原话?还缺哪条才不歧义?"
```

```
【C 判据】多写:
样例表(≥3好 ≥3坏,场景+用户评语均[原文]),另列边界例(用户犹豫或前后评价不一)
现行判据: ___ (关键词表/阈值/提示词里的哪句)
震荡史: v1太松,漏了___ → v2太紧,误伤___ → v3 ...
错误代价: 宁可漏(该停没停)还是宁可误伤(不该停却停)?用户表态 [原文/未问过]
根治加一条: 在用户没见过的_个新样例上,判定与用户一致≥_个;且判据不含针对单个样例的特判
用户说"治标"的原话 + 当时那版补丁是什么
少写: 背景压到1–2行;代码几乎不贴。
问题句式: "这些好坏例之间真正的区分特征是什么?我现在用的特征(___)为什么注定震荡?"
```

```
【D 长尾】多写:
时间线(每行一次)写进第4节: 会话_ / 用户说法[原文] / 我的假设 / 我宣称的结果 / 后来实际怎样
用户换过的说法并列: ①"_" ②"_" ③"_";它们是同一件事吗?我的拆分: 甲=___,乙=___
前提清单(≥3条,把"一直默认成立"的都列出): P1___ [已证实:怎么证的]  P2___ [未验证]
基准: "对"的参照是什么(数值/参考图/参考实现)? [有:___ / 没定过]
已知坑核对: 查过坑笔记和历史会话了吗?命中: ___
每次"修好"是怎么验证的: ___ (只在单一样例上看过=没验证)
少写: 新方案细节一律不写;代码≤15行。
问题只许问前提: "哪条前提错了/哪两个概念被我混了",不许问"下一个方案是什么"。
```

## 6 发问前的拦截清单（任一条答"是"就不发）

```
1. 这个答案只能通过读我机器上的文件、日志或运行命令得到吗?            → 去取证
2. 一条命令、一次搜索或查一次官方文档就能回答吗?(装哪个包/端口通不通/镜像怎么配) → 去执行
3. 我问的是"哪个更便宜/哪个入口/哪个版本"这类选型事实吗?             → 查价格表或文档,或问用户
4. 问题里有"这个/那个/上次那个",而我写不出它的绝对路径或确切名称吗?   → 先向用户确认指代
5. 我还没确认当前工作区/分支/文件就是用户说的那个吗?                  → 先确认
6. 这是"X有没有接上/数值在两种工具间怎么换算"这类能直接测出来的吗?    → 做一次测量或对照
7. 涉及多条链路(私聊/群聊/插件),而我还没画出每条的注入点吗?         → 先画链路图;画完仍解释不了差异,再按A类发
8. 已试清单里的"失败"是我推测的,而不是亲眼观测到的吗?                → 先去观测
9. 我能写出"专家会说X",且X能在10分钟内验证吗?                       → 先验证X
10. 我还没查坑笔记和历史会话里有没有同一症状吗?                       → 先查;命中就按已知坑处理
11. 我缺的其实是用户的偏好、参照物或原话吗?                           → 问用户,专家不知道用户想要什么
12. 把证据删掉后,我的问题只剩"帮我看看哪错了/怎么办"吗?              → 重写第10节
```

## 7 反向清单（任一条答"是"就必须发，不许再自己试）

```
R1. 同一症状这是第2次(或以上)出现,或跨了会话?
R2. 我曾宣称"修好了",之后又复现?
R3. 用户说过"治标""还是不对",或把同一要求换了≥3种说法?
R4. 自上次用户发言后工具调用>30次,而已证伪假设清单没有新增?
```

> R4 的 30 已按本机 89 个长尾会话校准：每次用户发言之间的工具调用中位数 16.6、p75 = 29.6、p90 = 46.9。30 约等于 p75，作为「你已经在硬磨」的信号是合理的。

## 8 参照：一个合格示例与一个不合格示例

合格（D 类，握持姿态）：关键在「我的度量 9 点全过，但用户 9 张截图不认」——把问题从「偏移量调多少」改成「基准是什么」。全文见 `docs/EXAMPLE-GOOD.md`。

不合格（要避免的写法）：
```
握持姿态问题求助
用户要角色拿着法杖,但姿态一直不对,调了很多次偏移和旋转都不行,
用户说还是歪的、像拿反了。我试了很多方法,现在不知道怎么办。
下面是完整代码和日志:(attach.js 全文 312 行)(控制台日志 1800 行)
请帮我看看哪里错了,给出修复后的完整代码。
```
它错在：没有「第几次」（专家会当新问题给第 5 版补丁）；「试了很多方法」没有清单（前三条建议全是你试过的）；没有根治定义（「不对/歪」没有基准）；整文件整日志（淹掉关键证据）；没有可观测中间态（专家只能让你加日志）；问题是「哪里错了给完整代码」（思考外包）；用户原话被概括（四种说法里「位置」和「朝向」两条线索丢了）。
